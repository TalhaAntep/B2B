# DealerSystemSetting mapping audit

## Current reconciled status — 2026-11-22

- Catalog: 98 unique controls; fixed authenticated Development-only settings API adapters: 93; separate application-owned image slots: 5.
- Five controls persist through application-owned extension settings because no legacy column was established: `ParameterProductDetailNotLogin2`, `ParameterMenu2`, `WhatsAppOrderNotification`, `FavoriteIconPosition`, and `FavoriteIconVerticalPosition`. Old portal reads are unverified. `ParameterProductSearch` is hybrid, using the SQL `smallint` low word and the app-owned `ParameterProductSearch.HighMask` extension key.
- `ParameterPayment` uses a signed SQL `smallint` representation of its unsigned 16-bit bit pattern. The original DOM evidence assigns option `1` to `ddlParameterModules` / `DealerSettings.ParameterModules` (`int`); option `32` belongs to `ddlParameterAdmin` / `DealerSettings.ParameterAdmin` (`bigint`).
- All 93 settings adapters have authenticated isolated API save/readback/restoration evidence. All five app-owned asset slots have isolated application asset API evidence. None of these tests proves legacy Web Forms save behavior; legacy save behavior is unknown for all 98 controls.
- This final delivery pass did not rerun backend or SQL integration suites. The latest final SQL checks were SELECT-only. Normal API mode is read-only and test-write flags are disabled.
